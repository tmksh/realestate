マンション発信ツール システム仕様書

未公開マンションを公式LINEで先出し配信するモックです。役割、画面、操作の流れ、実装済みとデモだけの切り分けをまとめます。APIキーやパスワードは書かない。

1. システム概要

SUUMOなどへ一般公開する前の短い期間を使い、既存のLINE会員へ先に物件を届けます。

マンション発信ツールは、ポータル掲載前の未公開マンションを管理会社が登録し、運営が確認・目隠ししたうえで公式LINEへ配信し、反応した会員をリスト化します。この文書は、初めて見る人が全体像を把握するための仕様書です。

いま見ているのはモック環境です ログインは担当者をクリックするだけです。公式LINEへの実送信、会員の実データ、サーバー側の保存はありません。

ROLE

管理会社

未公開物件を登録し、運営へ送ります。自社物件だけが見えます。

ROLE

運営

内容確認、番地などの目隠し、配信形式の指定、LINE配信、反応と会員の確認、オーナー発行を行います。

ROLE

オーナー

運営が割り当てた物件だけを、管理会社と同じ画面で確認します。新規登録はできません。

2. システム全体の業務フロー

物件は管理会社から始まり、運営の確認を経て配信されます。修正が必要なら差戻します。

トップから入れるのは管理会社と運営だけです。オーナーは運営画面の「表示を確認」から入ります。

6. 主要機能

物件登録／下書き保存

管理会社が未公開物件を入力します。必須が揃っていなくても下書きとして残せます。写真は用意済みURLから選びます。

運営への送信

必須が揃うと送信できます。状態は確認待ちになり、管理会社側は編集できなくなります。

目隠し

番地、部屋番号、マンション名、価格を配信文とプレビューから隠せます。運営の確認画面では元データが見えます。管理費・積立と申し送りのトグルは確認画面にありますが、配信文には出ないため表示は変わりません。

配信形式とプレビュー

箇条書き／カード／PDFから選びます。右（または下）にLINE風の見本が出ます。実トーク画面ではありません。PDFはファイル名の表示だけです。

差戻し

理由を書いて管理会社へ返します。LINE配信はしません。管理会社は理由を見て直し、再送信します。

配信履歴と反応

配信済み物件、人数、反応件数を残します。反応はいいね／スタンプ／テキストです。配信直後はデモ用に数件入ります。

LINE会員

公式LINE登録者の見本12名を出します。KPIと画面上の配信対象は248名です（12＋236の仮加算）。

オーナーと表示切替

オーナーを発行し、見える物件を指定します。確認待ちと配信履歴はカード／一覧を切り替えられ、選択は両画面で共有されます。

7. ステータス

通常は左から右へ進みます。確認待ちからは差戻しも選べます。

下書き → 確認待ち → 配信準備 → 配信済み
確認待ち → 差戻し → 再送信で確認待ち
状態 いつなるか 管理会社 運営
下書き 新規作成、または保存のみ 編集・送信できる 確認待ち一覧には出ない
確認待ち 運営へ送信した直後 ロック。編集不可 確認、保存、配信、差戻し
配信準備 運営が確認内容を保存 ロック 配信できる。確認待ち一覧にも残る
配信済み 「公式LINEで配信」後 ロック 再配信不可。履歴と反応を見る
差戻し 運営が理由付きで返す 再編集・再送信できる 確認待ち一覧に残る

10. LINE連携（本番でつなぐ場合）

いまの画面はモックです。本番では LINE公式アカウントの Messaging API を使います。以下は、このツールとしてどこまでできるかと、つなぎ方です。出典は LINE Developers 公式 です。トークンやパスワードは書きません。

このツールで必要な連携は2つです ① 友だちへ物件メッセージを送る。② 友だち追加・テキスト・スタンプ・ボタン操作を受け取る。LINEの全機能は使いません。メールや電話番号は取れません。

10-1. どこまでのことができるか

本番でつないだあと、このツールとして使う範囲です。LINE公式アカウントに備わっている機能の全部ではありません。

できる（このツールで使う）

送る・受け取る

  • 友だち全員へ同じ物件を送る
  • 会員を指定して一部だけに送る
  • 1人へ個別に送る（反応への返信など）
  • テキスト、画像、カード型で物件を見せる
  • メッセージ上のボタンで「気になる」を受け取る
  • 友だち追加と離脱を会員一覧に反映する
  • テキスト・スタンプを反応として残す
  • 表示名と画像を会員名に使う
  • 当月の API 送信通数の目安を取る

LINE上はできるが使わない

このツールの対象外

  • グループトークへの参加・送信
  • トーク下のリッチメニュー
  • ビーコン（店舗の接近検知）
  • 年齢・地域などの属性で絞る配信
  • 動画・音声・位置情報・クーポンの送信
  • LINEログインやLIFFアプリ
  • 自社会員IDとLINEの画面上の紐づけ

できない

APIの外／別契約

  • 友だちが読んでいないトークの中身を見る
  • Facebookのような「いいね」を公式機能として取る
  • メール・電話・本名・住所を Messaging API だけで取る
  • ブロック中の人には届かない。他社公式アカウントの友だちには送れない
  • PDFファイルそのものをLINEに置いて開く（URL案内は可）
  • 過去のトーク履歴をさかのぼって全部取る
  • 料金プランの通数上限を超えた無制限配信
やりたいこと できるか 補足
未公開物件を友だちのトークへ先出しする できる 全員へ同じ文面、または会員指定。1回の送信でメッセージは最大5個
誰が友だち追加し、誰が離脱したかを知る できる 接続後の follow / unfollow から分かる。unfollow はブロックと友だち解除の両方。つなぐ前の友だち全員のID一覧は、認証済またはプレミアムアカウントだけ
表示名で会員を一覧する できる 友だちであり、プロフィール提供に同意していることが条件
テキストやスタンプの反応を物件に紐づける できる 届いたときから記録する。過去分は取れない
画面の「いいね」と同じ操作 ボタンで代用 LINEにいいねAPIはない。カードやFlexのボタンを押した合図を使う
箇条書き／カード形式で見せる できる 本番ではテキスト＋画像、または Flex Message。モックの見た目そのものではない
PDFをトークで開く 一部だけ ファイルそのものの配信はしない。リンク付きの案内にする
反応した人へ個別に返事する できる 1人への送信。自動返事も可能だが、公式アカウント側の応答メッセージと二重にならないよう注意
地域や年齢で送り先を絞る 使わない LINE側の絞り込み配信は別機能。統計情報の利用同意が必要
メールや電話で追客する できない Messaging API の範囲外。ログインや Profile+ の契約と同意が必要
読んでいない人のトークを運営が見る できない 届いたメッセージとボタン操作だけがサーバーに来る
無制限に毎日送る できない 料金プランごとに月の通数上限がある。届いた人数が通数になる

通数は届いた人数で数えます。ブロック中など届かない人は数えません。Messaging API で取れる通数は API 経由の送信です。Official Account Manager からの配信は、料金プランの通数には含まれます。

10-2. LINE側から取れる情報

取得できる項目は、使うAPIで違います。メインプロフィールのみです。サブプロフィールは取れません。ユーザーIDはプロバイダーごとに別になります。

情報 Messaging API
（公式アカウント）		 LINEログイン / LIFF
（同意が必要）		 このツールでの使い方

表示名 取れる（displayName） 取れる（スコープ profile） 会員一覧・反応リストの表示名
プロフィール画像 取れる（pictureUrl） 取れる 任意。一覧のアイコン

Messaging API でプロフィールを取るには、友だちであることと、ユーザーがプロフィール提供に同意していることが条件です。エンドポイントは GET https://api.line.me/v2/bot/profile/{userId} です。

友だち全員のユーザーID一覧（GET /v2/bot/followers/ids）は、認証済アカウントまたはプレミアムアカウントだけです。

10-3. 配信の種類

種類 対象 このツール
ブロードキャスト 友だち全員に同じ文面 「公式LINEで配信」の本番相当
マルチキャスト ユーザーIDを指定して複数人へ 特定会員だけに送る場合

メッセージの形はテキスト、画像、テンプレート、Flex Message などです。本ツールの「箇条書き／カード／PDF」は、本番ではテキスト＋画像、または Flex Message に置き換えます。PDFはファイルそのものではなく、URL付きの案内にするのが一般的です。

10-4. 連携の具体的な手順

  1. ビジネスIDを作る。 LINE Official Account Manager で、LINEアカウントまたはメールアドレスからビジネスIDを登録する。
  2. 公式アカウントを作る。 作成フォームにアカウント名などを入れて保存する。既存の公式アカウントがある場合はそれを使う。
  3. Messaging API を有効にする。 Official Account Manager の設定から Messaging API をオンにする。ここで Messaging API チャネルが作られる。プロバイダーは後から変更できないので、同じ会社のログインやLIFFと同じプロバイダーを選ぶ。
  4. LINE Developers コンソールを開く。 同じログインで developers.line.biz/console に入り、作られたチャネルを確認する。コンソールから Messaging API チャネルを新規作成する手順は 2024年9月以降廃止されている。
  5. チャネルシークレットを控える。 ［チャネル基本設定］のチャネルシークレットをサーバー側の環境変数に入れる。画面や仕様書には書かない。
  6. チャネルアクセストークンを発行する。 ［Messaging API設定］で発行し、サーバー側の環境変数に入れる。公式の推奨はチャネルアクセストークン v2.1 です。ボットが配信APIを呼ぶときに使う。
  7. Webhook 用のHTTPSサーバーを用意する。 例: https://（自社ドメイン）/api/line/webhook。自己署名証明書は不可。ブラウザが信頼する証明書が必要。
  8. Webhook URL を登録する。 コンソールの［Messaging API設定］→ Webhook URL を編集 → 更新 →［検証］が成功することを確認 →［Webhookの利用］をオン。
  9. 署名を必ず検証する。 受信時にヘッダー x-line-signature を、チャネルシークレットによる HMAC-SHA256 で照合する。一致しないリクエストは捨てる。
  10. 空の検証リクエストに 200 を返す。 LINEからの確認は {"destination":"…","events":[]} の POST になる。ボディが空でも 200 を返す。
  11. 応答設定を決める。 ボットが返事する場合は、Official Account Manager の「応答メッセージ」と「あいさつメッセージ」をオフにする（二重応答を防ぐ）。
  12. 友だち追加して確認する。 コンソールの QR から公式アカウントを友だち追加する。サーバーログに follow が届くこと、ブロックまたは友だち解除で unfollow が届くことを確認する。
  13. 配信を試す。 サーバーから POST https://api.line.me/v2/bot/message/broadcast に Bearer トークンとメッセージJSONを送る。友だちのトークに届くことを確認する。
  14. 反応を保存する。 届いた Webhook の source.userId と、テキスト／スタンプ／ポストバックを、本ツールの反応リストと同じ形でサーバーに残す。

10-5. このツールの画面との対応

画面の操作 本番で呼ぶもの
「公式LINEで配信」 ブロードキャスト（または会員ID指定のマルチキャスト）
LINE会員一覧 follow で追加し、プロフィールAPIで表示名を補完。離脱（ブロックまたは友だち解除）は unfollow
反応の「テキスト」 message イベント（type: text）
反応の「スタンプ」 message イベント（type: sticker）
反応の「いいね」 LINEにいいねAPIはない。テンプレート／Flex のボタンをポストバックにし、data に物件IDを入れる

10-6. サーバー側の処理（Webhook受信後）

  1. 生のリクエストボディを保存したうえで署名を検証する（パース後のJSONで署名すると失敗する）。
  2. イベント配列を1件ずつ見る。source.userId が無いイベントは捨てる。
  3. follow … 会員を追加。続けてプロフィールAPIで表示名と画像を取る。
  4. unfollow … 会員を停止。配信対象から外す。ブロックと友だち解除のどちらでも同じイベントです。
  5. message（text）… 反応（テキスト）として物件と紐づける。直近配信の物件IDをサーバー側で持つ。
  6. message（sticker）… 反応（スタンプ）。必要なら特定スタンプIDを「気になる」とみなす。
  7. postback … data が like:<物件ID> なら反応（いいね）。
  8. 処理できたら HTTP 200 を返す。長い処理はキューに回し、先に 200 を返す。
いまのモックでは未接続です 「公式LINEで配信」を押しても実送信しません。チャネルシークレットとアクセストークンは環境変数にだけ置き、GitHub や仕様書には載せないでください。

公式ドキュメント：Messaging APIの概要 ／ Messaging APIを始めよう ／ ボットを作成する ／ ユーザーのプロフィール情報を取得する ／ メッセージを送信する

10-7. LINE公式アカウントの費用（別費用）

この費用は本ツールの開発費・サーバー費とは分けて扱う別費用です。日本のLINE公式アカウントの料金です。金額は税別です。最新額はLINEヤフーの公開ページを正とします。

出典：Messaging APIの料金（LINE Developers）、LINE公式アカウント料金プラン（いずれも2026-09-24確認）。

月の無料メッセージ通数と、超えたときの費用

開設時はコミュニケーションプランです。ライト／スタンダードへ変えると、その月から無料通数が増えます。初期費用はありません。

プラン 月額固定費（税別） 無料メッセージ通数（月） 無料通数を超えたとき
コミュニケーション 0円 200通 追加配信はできない。送りたい場合は上位プランへ変更する
ライト 5,000円 5,000通 追加配信はできない。送りたい場合はスタンダードへ変更する
スタンダード 15,000円 30,000通 追加メッセージを送れる。通数に応じた従量料金（税別、最大おおよそ3円／通）

通数は「届いた人数」です。1回の配信で友だち248人に届けば248通です。吹き出しを複数置いても、通数は人数分です。ブロック中など届かない人は数えません。応答メッセージ（Reply API）は通数に入りません。ブロードキャスト／マルチキャスト／プッシュは入ります。Official Account Manager からの配信も、料金プランの通数に入ります。

コミュニケーション／ライトで上限を超えると、メッセージは送られず、自動では課金されません。スタンダードで追加メッセージを使うには、Official Account Manager で追加メッセージ数の上限目安を設定します。上限を超えて送ろうとすると、原則として配信は止まります。

スタンダードの追加メッセージ単価は、追加した通数帯によって下がります（税別）。公式の例では、追加200,000通のとき （50,000×3円）＋（50,000×2.8円）＋（100,000×2.6円）＝550,000円 です。2026年10月1日から追加メッセージ料金が改定され、追加20万通／月までは1通3円、それを超えた分は1通2.5円（税別）になります。改定の詳細はLINEヤフーの告知を正とします。

別費用として扱う範囲 月額固定費と、スタンダードで発生した追加メッセージ料金です。チャットProやプレミアムIDなど任意オプションは、配信通数の費用とは別契約です。このモックでは実課金は発生しません。

売上の原価と利益の分け方

上記の別費用は、売上から原価として差し引きます。差し引いたあとに残った利益を、泉さんと折半します。

計算の考え方は次のとおりです。

  1. 売上を集計する
  2. その月のLINE公式アカウント費用（月額固定費＋追加メッセージ料金）を原価として差し引く
  3. 残った利益を、泉さんと半分ずつにする

例：売上が100、その月のLINE公式アカウント費用が20なら、利益は80。泉さん40、相手方40です。実額は契約と請求に従います。この仕様書は配分の考え方だけを書きます。

13. 制約・注意事項

  1. 本番システムではなく、操作確認用のモックです。
  2. 「公式LINEで配信」を押しても、実際のLINEには届きません。
  3. データは操作したブラウザにしか残りません。消す・別の端末では初期状態です。
  4. 会員一覧は再読み込みのたびに初期12名へ戻ります。248名は仮の加算です。
  5. 目隠しは配信文とプレビューに出る項目（番地、部屋番号、マンション名、価格）に効きます。運営の確認画面では元データが見えます。
  6. 管理会社は送信後に編集できません。修正は運営の差戻しが必要です。
  7. オーナーはトップから入れません。運営の「表示を確認」経由です。招待中・停止中は入れません。割り当てた下書き・差戻しは編集できます。
  8. 確認待ち一覧には、差戻し済みの物件も含まれます。
  9. カード／一覧の選択は、確認待ちと配信履歴で共有されます。
  10. LINE公式アカウントの月額固定費と追加メッセージ料金は別費用です。売上の原価として差し引き、残った利益を泉さんと折半します。通数と単価は「10-7. LINE公式アカウントの費用」を正とします。
  11. この仕様書は GitHub Pages（docs/）で公開します。アプリ本体はローカルの Next.js です。
  12. 実行基盤は Next.js 16 の App Router です。
  13. 写真は Unsplash に依存します。オフラインやリンク切れでは画像が出ないことがあります。
