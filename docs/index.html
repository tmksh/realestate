マンション発信ツール システム仕様書

未公開マンションを公式LINEで先出し配信するモックです。役割、画面、操作の流れ、実装済みとデモだけの切り分けをまとめます。APIキーやパスワードは書かない。

アプリ
Vite 8 / React 19 / React Router 7
保存
ブラウザの localStorage のみ

GitHub Pages（docs/）
状態
モック / 実データ未接続

1. システム概要

SUUMOなどへ一般公開する前の短い期間を使い、既存のLINE会員へ先に物件を届けます。

マンション発信ツールは、ポータル掲載前の未公開マンションを管理会社が登録し、運営が確認・目隠ししたうえで公式LINEへ配信し、反応した会員をリスト化します。この文書は、初めて見る人が全体像を把握するための仕様書です。

いま見ているのはモック環境です ログインは担当者をクリックするだけです。公式LINEへの実送信、会員の実データ、サーバー側の保存はありません。

ROLE

管理会社

未公開物件を登録し、運営へ送ります。自社物件だけが見えます。

ROLE

運営

内容確認、番地などの目隠し、配信形式の指定、LINE配信、反応と会員の確認、オーナー発行を行います。

ROLE

オーナー

運営が割り当てた物件だけを、管理会社と同じ画面で確認します。新規登録はできません。

2. システム全体の業務フロー

物件は管理会社から始まり、運営の確認を経て配信されます。修正が必要なら差戻します。

1. 物件登録管理会社が未公開マンションを入力
→
2. 下書き保存必須以外は後から補える
→
3. 運営へ送信確認待ちになり、以降は編集ロック
4. 確認・目隠し番地などを配信文から隠す
→
5. LINE配信実送信せず、反応を自動で足す
→
6. 反応確認いいね／スタンプ／テキストを一覧化
分岐：差戻し 情報が不足している場合、運営は確認待ちから差戻します。管理会社が直して再送信すると、再び確認待ちになります。差戻しではLINE配信は行われません。

3. 権限・ユーザー種別

トップから入れるのは管理会社と運営だけです。オーナーは運営画面の「表示を確認」から入ります。

役割 入り方 見られるもの できること できないこと
管理会社 トップで田中／鈴木を選ぶ 自社物件だけ 登録、下書き保存、運営へ送信、自社の反応確認 他社物件、配信操作、会員・オーナー管理
運営 トップで泉担当を選ぶ 全物件、配信、反応、会員、オーナー 確認、目隠し、配信、差戻し、オーナー発行 管理会社としての物件新規登録画面は使わない
オーナー オーナー管理の「表示を確認」 割り当て物件だけ 割り当て物件の閲覧（ロック中は編集不可） 物件の新規登録、配信、会員管理。招待中・停止中は入れない

6. 主要機能

物件登録／下書き保存

管理会社が未公開物件を入力します。必須が揃っていなくても下書きとして残せます。写真は用意済みURLから選びます。

運営への送信

必須が揃うと送信できます。状態は確認待ちになり、管理会社側は編集できなくなります。

目隠し

番地、部屋番号、マンション名、価格、管理費・積立、申し送りを配信文から隠せます。運営の確認画面では元データが見えます。

配信形式とプレビュー

箇条書き／カード／PDFから選びます。右（または下）にLINE風の見本が出ます。実トーク画面ではありません。PDFはファイル名の表示だけです。

差戻し

理由を書いて管理会社へ返します。LINE配信はしません。管理会社は理由を見て直し、再送信します。

配信履歴と反応

配信済み物件、人数、反応件数を残します。反応はいいね／スタンプ／テキストです。配信直後はデモ用に数件入ります。

LINE会員

公式LINE登録者の見本12名を出します。KPIと画面上の配信対象は248名です（12＋236の仮加算）。

オーナーと表示切替

オーナーを発行し、見える物件を指定します。確認待ちと配信履歴はカード／一覧を切り替えられ、選択は両画面で共有されます。

7. ステータス

通常は左から右へ進みます。確認待ちからは差戻しも選べます。

下書き → 確認待ち → 配信準備 → 配信済み
確認待ち → 差戻し → 再送信で確認待ち
状態 いつなるか 管理会社 運営
下書き 新規作成、または保存のみ 編集・送信できる 確認待ち一覧には出ない
確認待ち 運営へ送信した直後 ロック。編集不可 確認、保存、配信、差戻し
配信準備 運営が確認内容を保存 ロック 配信できる。確認待ち一覧にも残る
配信済み 「公式LINEで配信」後 ロック 再配信不可。履歴と反応を見る
差戻し 運営が理由付きで返す 再編集・再送信できる 確認待ち一覧に残る

8. データ仕様

サーバーは使わず、操作したブラウザの localStorage にだけ残ります。

キー 内容
aqualine-store-v2 物件、配信、反応、オーナー、いまのユーザー。会員一覧は起動のたびに初期12名へ戻します。
aqualine-sidebar 左メニューの開閉。
aqualine.catalogView 確認待ちと配信履歴のカード／一覧。両画面で共有。

保持される範囲

同じPC・同じブラウザだけです。シークレットモード、別端末、データの削除で初期状態に戻ります。JSONが壊れているとキーを消して初期化します。

初期データ（seed）

  • 管理会社：田中（サンライズ）、鈴木（港区アセット）
  • 運営：泉担当
  • 物件4件：白金台（確認待ち）、桜新町（配信済み）、浜松町（下書き）、品川（確認待ち）
  • 配信1件（桜新町）、反応9件、会員12名
  • オーナー：斎藤（利用中・桜新町と浜松町）、近藤（招待中）、森（停止中）

以前の操作がブラウザに残っていると、画面の件数は初期と違うことがあります。

9. 外部サービス・連携

見た目のために使っているものと、つながっているように見せているだけのものを分けます。

実際に使っている

GitHub Pages ／ Unsplash

  • この仕様書は GitHub Pages で公開します。フォルダは docs/ です。
  • 物件写真は Unsplash の画像URLです。自社ストレージではありません。

モックのみ

公式LINE ／ 会員 ／ メール

  • LINE Messaging APIはありません。配信ボタンは画面内の状態を変えるだけです。
  • 会員・反応の受信（Webhook）はありません。
  • オーナーのメールは保存するだけで、招待メールは送りません。
  • 自前のREST API・データベースはありません。

10. 技術構成

画面の動きは Vite のシングルページアプリです。リポジトリに Next.js の名残はありますが、起動には使いません。

分類 採用 備考
実行 Vite 8、React 19、React Router 7 npm run dev で 127.0.0.1:3000
言語 TypeScript Node 20以上24未満
UI Tailwind CSS 4、Lucide 色は白・黒・グレー。LINE緑は配信まわりのみ
状態 React Context + localStorage キーは aqualine-store-v2
仕様書の公開 GitHub Pages リポジトリの docs/ を配信します
アプリの起動 ローカルの Vite 深いURLを直接開くには、ホスト側で全パスを index.html に返す設定が必要です
使っていない残ファイル Next.js 16、next.config.ts、一部 layout 仕様上の実行基盤は Vite です

12. 制約・注意事項

  1. 本番システムではなく、操作確認用のモックです。
  2. 「公式LINEで配信」を押しても、実際のLINEには届きません。
  3. データは操作したブラウザにしか残りません。消す・別の端末では初期状態です。
  4. 会員一覧は再読み込みのたびに初期12名へ戻ります。248名は仮の加算です。
  5. 目隠しは配信文とプレビューに効きます。運営の確認画面では元データが見えます。
  6. 管理会社は送信後に編集できません。修正は運営の差戻しが必要です。
  7. オーナーはトップから入れません。運営の「表示を確認」経由です。招待中・停止中は入れません。
  8. 確認待ち一覧には、差戻し済みの物件も含まれます。
  9. カード／一覧の選択は、確認待ちと配信履歴で共有されます。
  10. この仕様書は GitHub Pages（docs/）で公開します。アプリ本体はローカルの Vite です。
  11. 実行基盤は Vite のSPAです。Next.jsのファイルが残っていても、起動には使いません。
  12. 深いURLを直接開くには、静的ホスト側で全パスを index.html に返す設定が必要です。
  13. 写真は Unsplash に依存します。オフラインやリンク切れでは画像が出ないことがあります。
